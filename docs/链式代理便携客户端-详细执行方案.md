## 1. 项目目标与技术路线

开发一款 Windows 链式代理客户端，将 Clash Verge Rev 的配置、内核管理和托盘能力一同打包，提供简化首页。用户解压后首次导入机场订阅，填写静态出口代理信息，选择前置节点，即可检测并建立连接。

基本链路：用户应用 → 本地代理内核 → 前置节点 → 用户指定的 SOCKS5 出口 → 目标网站。配置为直连的流量按规则单独处理。

确定采用以下路线：

| 项目 | 首版决策 |
| --- | --- |
| 产品形态 | Clash Verge Rev 的定制分支，使用自己的产品名称与应用标识 |
| 实现方式 | 在现有前端增加简化首页，在 Rust 后端实现参数校验、配置生成、连接检测和便携目录管理 |
| 初始技术基线 | Clash Verge Rev v2.5.9，固定提交 `160bb4fe8eaef2bc626163d89622229e5d7c5b59`，以该提交锁文件为起点 |
| 内核 | mihomo v1.19.33，Windows amd64-v2；压缩包和可执行文件哈希见技术基线清单 |
| 首批平台 | Windows 11 25H2 / 26H2 x64，最低 OS build 26200；Windows 10 22H2 x64 仅作为后续兼容性候选 |
| 出口协议 | SOCKS5，首版支持 IPv4 地址或域名形式的服务地址 |
| 订阅格式 | 首版支持 Clash/Mihomo YAML 文件和 HTTPS 订阅链接 |
| 默认运行方式 | 普通系统代理，无需安装常驻服务 |
| TUN | v1.0 首发隐藏，后续独立验收后开放；首发不安装常驻服务或额外驱动 |
| 分发形式 | ZIP 文件夹，包含程序、内核、规则资源、说明与许可材料 |
| 收费基础 | 签名构建、版本维护、技术支持和部署服务；客户端分发遵守 GPL |

Clash Verge Rev 现有代码已经使用 Tauri、React/TypeScript 和 Rust；实施时沿用上游技术栈与锁文件，不为首版再引入一套桌面框架。[上游前端构建配置](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.9/package.json)、[Rust 项目配置](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.9/src-tauri/Cargo.toml)

## 2. 已有基础与需要修正的问题

### 2.1 本次会话已经确认的事实

此前的本机只读检查确认：客户端版本为 2.5.9；存在全局扩展脚本；脚本通过 `dialer-proxy` 将 SOCKS5 出口连接到前置节点池；内核当时处于规则模式且 TUN 开启，运行选择与连接记录符合这套链路。

这些记录是检查时的快照，不代表持续监控，也不证明出口属于住宅、独享或永久固定 IP。商品中应使用“用户指定出口”等可验证表述；“静态”属性由用户与供应商确认。

### 2.2 首版必须解决的现有问题

| 问题 | 对其他用户的影响 | 实施要求 |
| --- | --- | --- |
| 现有协议白名单遗漏 AnyTLS | 当前配置中的 33 个 AnyTLS 条目未进入前置池 | 采用版本化协议能力表，并加入 AnyTLS 真实链路测试 |
| 公告条目进入节点池 | 测速与选择结果混乱 | 结合结构、必要字段、重复条目及名称提示识别，允许用户排除 |
| 同一出口以不同名称混入前置池 | 出口可能再次成为前置候选 | 按规范化端点比较，默认排除与出口主机及端口相同的前置 |
| 仅测试前置节点 | 出口不可用时仍可能显示正常 | 增加通过完整链路发起的 HTTPS 与出口 IP 检测 |
| 无节点时插入 DIRECT | 实际路径偏离用户预期 | 返回明确错误，保持受代理流量阻断，不隐式直连 |
| 最终出口组仅手动选择 | 出口失效时没有明确处理流程 | 设计故障状态、重试与恢复操作 |
| 全局替换代理组和规则 | 影响其他订阅与已有分流 | 使用独立的产品配置，保留源订阅，限定自定义项 |
| 出口凭证硬编码且重复保存 | 更新困难，打包时容易泄露 | 参数与代码分离，凭证集中管理，发布包使用空白模板 |

现有脚本只用于理解行为和构造脱敏测试样本，不直接作为发布模板。定制版的正式逻辑放入可测试的配置生成模块，避免依赖用户手动编辑全局脚本。

## 3. 首版范围与版本划分

### 3.1 v0.1：内部验证版

- 能从固定源码构建，使用独立应用标识和数据目录启动。
- 能导入一个 YAML 订阅，配置一个 SOCKS5 出口，手动选择前置。
- 能生成、校验并运行代理链，显示真实出口 IP。
- 能正常退出并恢复本程序修改的系统代理。
- 不接入支付，不公开分发，不导入本人的真实凭证作为测试夹具。

### 3.2 v0.9：付费试用候选版

- 支持 HTTPS 订阅更新、节点过滤、前置自动选择和错误诊断。
- 完成便携路径、端口、进程和 WebView2 数据隔离。
- 完成配置回退、异常恢复、脱敏诊断包和新手指引。
- 提供普通连接模式；TUN 若未通过验收，则隐藏并单独延期。
- 面向 10 名符合目标条件的用户试用，其中至少 5 名真实付费。

### 3.3 v1.0：可维护的公开发行版

- 通过本文件的发布验收，完成源代码、许可与构建资料交付。
- 提供标准包和内置 WebView2 的完整包。
- 固定支持范围、价格、服务时长、退款处理和问题反馈渠道。
- 支持受验证的升级与恢复流程。

### 3.4 延后范围

首版暂不承诺 macOS/Linux/ARM64、多订阅合并、多账号隔离、多出口并发、浏览器指纹隔离、系统级断网保护、远程修复驱动、通用订阅转换服务、常驻高权限服务、运营线路或带宽转售。

高级页面仅保留确实完成隔离和测试的功能。会修改注册表关联、安装服务、开启自动更新或覆盖配置的上游入口，应在完成适配前隐藏。

## 4. 用户流程与界面要求

### 4.1 首次启动

1. 检查操作系统、架构、目录写入能力和 WebView2。
2. 初始化独立数据目录和产品实例，不读取原 Clash Verge 配置。
3. 提示用户导入自己的订阅链接或本地 YAML。
4. 输入出口代理地址、端口、用户名和密码，可选择是否保存凭证。
5. 展示可用前置节点，默认手动选择，另提供“自动选择”。
6. 点击“检测并连接”，先在隔离的诊断内核中验证链路。
7. 检测通过后应用正式配置，启动工作内核，再接管系统代理。
8. 再次通过工作内核检查出口，显示连接状态与检测时间。

首次需要导入订阅，软件才能提供节点列表。后续可记住非敏感参数与选择。若用户未保存密码，重新启动后需补充认证信息。

### 4.2 首页内容

| 区域 | 展示内容 | 行为要求 |
| --- | --- | --- |
| 出口配置 | 地址、端口、用户名、密码 | 密码默认遮蔽；粘贴与特殊字符正确处理 |
| 订阅 | 订阅名称、更新时间、更新按钮 | 链接默认隐藏，不展示认证参数 |
| 前置选择 | 节点名称、协议、检测结果、手动或自动 | 名称作为文本渲染；过滤掉不支持和不完整条目 |
| 连接控制 | 检测并连接、断开、重新检测 | 操作中防重复提交，允许取消检测 |
| 当前状态 | 前置节点、观察到的出口 IP、检测时间、模式 | 本地端口开启不代表链路健康 |
| 故障提示 | 出错环节、简明解释、下一步操作 | 原始技术错误放入高级详情，先脱敏 |
| 高级设置 | 分流预设、日志、备份恢复、TUN、关于与许可 | 不把配置文件路径或内部接口作为必填步骤 |

### 4.3 表单约束

- 出口地址接受 IPv4 或域名，不接受带路径的完整网页 URL；IPv6 出口延期支持。
- 端口范围为 1～65535；用户名与密码分别填写，不拼接进 shell 命令。
- 支持无认证 SOCKS5；用户名和密码的组合按服务端要求校验。
- 账号、密码和 URL 中的特殊字符使用标准解析器处理，不通过字符串切割猜测。
- 首版把 SOCKS5 认证 URI 粘贴解析作为可选便利功能，不作为手填流程的依赖。
- 节点由稳定内部 ID 识别；相同显示名称需要区分，不能只用名称保存选择。
- 所有外部文本做长度限制与转义，不将节点名称、订阅备注作为可执行内容。

## 5. 系统架构与模块职责

程序结构：简化界面 → Rust 业务接口 → 订阅解析与配置生成 → 内核管理 → 系统代理或可选 TUN。连接诊断、凭证保护和恢复记录由独立模块提供。

| 模块 | 输入与职责 | 交付要求 |
| --- | --- | --- |
| Bootstrap | 初始化产品标识、数据路径、依赖和实例锁 | 在日志、缓存和 WebView 初始化前确定路径 |
| ProfileImporter | 获取并解析用户订阅 | 保存原始来源与版本，产出结构化节点，不直接执行远程脚本 |
| CredentialStore | 保存出口密码和订阅令牌 | 本机加密，提供删除、重新输入和脱敏读取接口 |
| ChainBuilder | 将节点、出口、分流预设编译为配置 | 纯数据处理，结果确定、命名隔离、拒绝循环引用 |
| CoreManager | 启动、检查、切换和停止本产品内核 | 只管理自己创建的进程，记录版本和实例身份 |
| ChainProbe | 检测前置、完整链路和实际出口 | 请求路径显式指定，不依赖系统当前代理 |
| ProxySession | 接管与恢复系统代理 | 事务化记录，只恢复本程序仍持有的设置 |
| RecoveryManager | 处理配置失败、进程崩溃和上次未退出 | 保留最后可用配置，提供受控恢复 |
| Diagnostics | 日志与诊断包 | 默认不包含明文凭证、完整订阅链接和访问历史 |
| ReleaseManager | 构建清单、更新验证和数据迁移 | 不复用上游自动安装更新通道 |

新增模块名称为本方案建议，并非上游已经存在的代码路径。实际目录在固定源码后确定。

## 6. 配置与节点处理

### 6.1 订阅导入

1. 用户明确输入链接或选中文件后才读取；不自动扫描磁盘上的其他客户端。
2. HTTPS 下载默认超时 20 秒、最多重试 2 次、限制重定向和响应体大小。初始响应上限建议 10 MiB，可根据试用数据调整。
3. 解析 YAML 时限制别名展开、嵌套深度和节点数量，拒绝不安全自定义标签。
4. 导入后保留源订阅，生成产品自己的工作配置，不回写用户提供的源文件。
5. 首版优先支持内联 `proxies`。遇到只有 `proxy-providers` 的订阅，明确提示暂不支持，不直接沿用其远程下载行为。
6. 只提取经过白名单校验的节点字段。订阅内的代理监听、控制接口、TUN、远程规则资源及其他程序行为不直接继承。
7. 订阅下载失败时保留最后可用内容；初次没有内容时停止连接并提示原因。
8. 若网络环境需要已有代理才能下载，提供用户明确选择的本地导入或指定本地代理选项，不静默使用不明代理。

### 6.2 节点筛选与协议支持

前置协议候选为 SS、VMess、VLESS、Trojan、AnyTLS；仅将通过固定内核实际测试的组合标记为支持。Hysteria2、TUIC、WireGuard 等组合列入后续能力矩阵，不以“内核认识该协议”代替整条链路验证。

筛选需要校验协议必需字段、服务地址、端口与重复项。公告条目的名称规则仅作辅助依据，避免误删正常节点。相同端点的多个不同认证节点保持独立身份。

默认排除与出口主机和端口相同的前置条目。对于 CNAME、多个域名指向同一服务等情形，检测结果只作辅助提示，不能声称已经证明端点完全不同。

### 6.3 链路生成

- 出口节点的 `dialer-proxy` 指向本产品的前置选择组。
- 最终出口组首版只包含用户指定的出口，不放入 DIRECT 或前置组作为自动备用。
- 前置池为空时返回错误，不补入 DIRECT。
- 所有产品生成节点和组使用内部保留命名空间，避免与源订阅名称冲突。
- 检查代理组及 `dialer-proxy` 依赖图，拒绝自引用、循环和不存在的目标。
- 同一输入重复生成应得到等价配置，不重复添加节点、组和规则。
- 使用配置序列化器写 YAML，通过固定内核支持的配置校验入口验证后再应用。

这种链路方向由 mihomo 的 `dialer-proxy` 机制提供：被配置的出口通过指定前置建立连接。旧的 `relay` 类型不作为新产品基础。[mihomo 链式代理文档](https://wiki.metacubex.one/config/proxies/dialer-proxy/)

### 6.4 分流与 DNS

提供“国内常用服务直连”和“全部受代理流量走指定出口”两种预设，并明确局域网例外。规则顺序、例外和最终 MATCH 均由产品模板生成；高级自定义使用单独的数据结构，不让任意脚本接管产品行为。

DNS 按固定内核版本设计：前置服务地址的启动解析不得依赖尚未建立的链路；目标域名解析按对应分流路径处理；用抓包和断链测试验证没有循环依赖。默认不启用用户未知的远程规则下载。

首版代理内核默认关闭 IPv6 支持，出口 IP 检测限定 IPv4；不擅自修改系统网卡 IPv6 设置。普通系统代理无法覆盖所有应用或未被代理的 IPv6 流量，界面与说明中需写清覆盖范围。

规则资源随包固定版本与哈希，记录来源和许可。资源更新经过校验并可恢复，不能因远程下载失败清空本地规则。

## 7. 连接检测、自动选择与状态机

### 7.1 检测分层

| 层级 | 检测方式 | 能证明什么 |
| --- | --- | --- |
| 参数层 | 校验字段、结构、组引用与内核配置 | 配置具备运行条件 |
| 前置层 | 通过候选前置访问指定 HTTPS 探测地址 | 该前置可完成相应请求 |
| 整链层 | 固定前置和出口，经隔离诊断内核发起请求 | 此组合在该时刻可完成请求 |
| 出口层 | 经相同链路访问 IP 查询服务 | 查询服务实际观察到的出口 IP |
| 工作层 | 正式接管后经工作内核复检 | 用户即将使用的配置与检测结果一致 |

所有探测请求显式指定本产品诊断或工作入口，避免因电脑原有代理而误判。诊断入口绑定本机随机端口，只开放 HTTP/SOCKS 代理，不开启 TUN，不修改系统代理。

IP 查询请求会把当前出口 IP 暴露给查询服务。首次说明检测用途，公布使用的检测服务，并提供关闭后台定时检测的选项。请求不附带订阅链接、用户名、密码或用户访问历史。

出口代理的连接地址可能不同于最终出网 IP，因此不直接要求两者相等。允许用户选填“预期出口 IP”；未填写时显示观察结果，由用户确认并可设置为后续比较基准。

### 7.2 自动选择

采用两阶段选取：先按前置探测筛选最多 3 个候选，再分别测试完整链路；在通过整链检测的候选中选取表现较好的一个。自动切换仅更换前置，保持用户指定出口配置。

建议初始参数：前置探测间隔 300 秒，完整链路健康检查间隔 60 秒，连续 3 次失败进入降级状态。间隔、超时及容差需要根据内测调整，并计入检测产生的连接数和流量。

切换前验证新组合，切换后复检。已有连接可能仍绑定旧链路，新连接使用新选择；是否关闭旧连接由用户主动选择，界面提示可能中断正在进行的任务。

### 7.3 状态机

状态至少包括：未配置、可连接、检测中、连接中、已连接、链路异常、断开中、已断开、需要恢复。

只有工作内核启动、配置应用成功且整链复检通过后，显示“已连接”。网络断开、唤醒或出口异常时更新状态，不保留长期失真的绿色状态。

固定出口失效后不自动改为前置直出或 DIRECT。继续保留本地代理入口并让相关代理请求失败；恢复后重试。用户主动断开意味着恢复原系统代理，界面应说明之后流量会按系统原有设置运行。

此策略约束的是本产品处理的代理路径，不提供系统级 Kill Switch 保证。对未遵循系统代理的应用、系统代理绕过规则及程序崩溃后的所有流量，首版不承诺全设备阻断。

### 8.3 同机共存

- 应用标识、实例锁、命名管道和内部控制认证与原版隔离。
- 默认不注册 `clash://` 或 `clash-verge://`，不读取原版订阅和缓存。
- 自动选择空闲本地端口；处理“检查时空闲、启动时被占用”的竞争并重试。
- 内核启动后验证身份和版本，不以端口可连接作为连接成功依据。
- 内核控制接口使用随机回环 TCP 端口与每实例随机令牌，关闭 mihomo 原生命名管道控制入口。自有守护进程的 IPC 使用显式限制当前用户访问的独立命名管道，具体约束见技术基线。
- 本地代理监听仅绑定回环地址；不启用局域网共享。
- 可以与原版同时打开；若双方均要接管系统代理，应提示用户选择，不能反复抢写。两个 TUN 同时接管不列为支持场景。
- 停止进程只针对本产品创建且身份匹配的进程，不按 `mihomo.exe` 名称批量结束。

## 9. 运行依赖与 TUN

### 9.1 WebView2 分发

提供标准包和完整包。标准包复用已有 WebView2；完整包携带经过验证的 Fixed Version Runtime，并显式指定运行时与用户数据目录。完整包需核对微软分发条款、系统要求和文件权限要求，纳入自己的安全更新周期。[微软 WebView2 分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)

开发阶段补充检查 VC 运行库等实际构建依赖。若依赖无法合法随包提供且目标系统缺少，明确提示解决方法，不承诺所有电脑都能零依赖运行。

### 9.2 普通模式

默认采用普通权限启动，不安装服务，不改开机启动，不注册 URL 协议。通过系统代理覆盖遵循该设置的应用；无法覆盖的应用可自行使用本地代理入口，或选择已通过验收的 TUN 功能。

### 9.3 TUN 模式

TUN 在 v1.0 首发隐藏。后续开放时，通过管理员授权启动本产品的受控内核流程，不安装常驻服务。官方说明普通权限下的 Sidecar 无法使用 TUN，管理员运行可在不安装服务的情况下使用。[官方 Windows 说明](https://www.clashverge.dev/faq/windows.html)

实施要求：

- 提权前验证产品自身与内核身份、签名或可信发布清单，失败时拒绝执行。
- 提权入口仅允许固定的内核操作，不接受任意命令、任意可执行路径或任意远程脚本。
- 探索并验证安全的用户态界面与提权执行边界；在允许普通用户修改的目录中直接长期运行 SYSTEM 服务，不作为方案。
- UAC 被取消时保留普通模式，不反复弹窗、不进入无响应状态。
- 明确 TUN 涉及虚拟网卡、路由和 DNS 等系统变更。免安装指应用无需安装器，不承诺系统没有任何状态变化或残留。
- 记录并恢复本产品创建的网络状态，不执行全局网络重置，不删除其他虚拟网卡。
- 检测到驱动或第三方虚拟化组件异常时，输出诊断结果，不自动搬用本机已有的驱动或注册表修复脚本。

若安全边界或干净系统测试未完成，v1.0 先发布普通模式，TUN 延期，不以降低权限检查换取演示成功。

## 10. 凭证、隐私与数据迁移

默认使用 Windows 当前用户范围的 DPAPI 保护长期保存的密码和订阅令牌。DPAPI 通常依赖同一用户和同一台电脑，因此跨电脑复制后需要重新输入凭证；产品应明确提示。[微软 DPAPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

为内核运行而生成的配置可能仍包含明文认证信息。优先验证受限临时文件或内存传入能力；必须落盘时使用仅当前用户及必要管理员可访问的权限，正常停止后尽力清理。不能宣称所有凭证始终处于密文状态，也不能保证崩溃后无残留。

数据处理规则：

- 不将凭证放入命令行、普通日志、错误通知或截图默认展示区。
- 日志对 URL 查询参数、userinfo、认证头、密码、UUID 等进行结构化脱敏。
- 普通备份默认不包含可直接复用的明文凭证，原始订阅缓存也按敏感数据处理。
- 跨电脑迁移首版采用重新输入凭证；口令加密导出作为后续功能，不能使用程序内置通用密钥。
- 诊断包默认包含版本、错误码、脱敏拓扑及必要时间信息，不包含浏览历史和完整连接明细。
- 用户导出前能预览范围，主动选择保存位置；软件不自动向维护者发送文件。
- 默认无遥测，未来如增加则独立说明目的、字段和关闭方式。
- 同机移动目录需测试；已运行期间不支持直接移动目录，检测到路径变化后要求先退出。

## 11. 配置更新、断开恢复与异常处理

### 11.1 配置应用事务

新参数 → 构建候选配置 → 内核校验 → 隔离整链检测 → 记录当前可用配置 → 应用工作配置 → 复检 → 提交版本。

候选失败不覆盖最后可用配置。工作配置应用后失败，恢复旧配置并提示；旧配置也无法运行时保留故障状态，不自动换出口。

### 11.2 系统代理接管与恢复

接管前保存当前用户的代理开关、服务地址、PAC 和绕过规则等必要状态，并把恢复记录先写入持久化日志。接管后记录本程序实际写入的值。

正常退出或断开时，只有当前设置仍匹配本程序写入的值，才恢复原值。如果用户或其他软件已经修改，停止覆盖并提供说明，避免恢复旧快照破坏新的设置。

采用产品独立的用户态守护进程处理主进程意外退出；守护进程只操作本产品仍持有的系统代理设置，不需要常驻 Windows 服务。验证主进程身份，不能仅按 PID 判断所有权。

主进程与守护进程均被强制结束时，无法保证立即恢复。需要在下次启动时识别未完成会话，并提供可独立打开的恢复入口。断电、强制关机和第三方同时改设置均纳入测试。

### 11.3 错误分类

| 错误码示例 | 用户提示 | 操作 |
| --- | --- | --- |
| SUBSCRIPTION_FETCH_FAILED | 无法更新订阅，正在保留上次内容 | 检查链接、网络或导入本地文件 |
| SUBSCRIPTION_UNSUPPORTED | 该订阅格式暂未支持 | 显示支持格式，不猜测转换 |
| NO_VALID_FRONT | 没有可用于前置的节点 | 更新订阅或检查过滤条件 |
| EXIT_AUTH_FAILED | 出口认证失败 | 检查用户名、密码及供应商要求 |
| FRONT_TO_EXIT_FAILED | 前置可用，但无法建立到出口的链路 | 尝试其他前置或检查出口限制 |
| EXIT_IP_CHANGED | 检测到出口 IP 与确认基准不同 | 显示旧、新值和检测时间，允许复检 |
| CORE_START_FAILED | 代理内核未能启动 | 展示脱敏错误和恢复操作 |
| PORT_BUSY | 本地端口被占用 | 自动换端口，失败后说明原因 |
| DATA_NOT_WRITABLE | 软件目录无法保存数据 | 提示移动到可写位置 |
| TUN_PERMISSION_DENIED | 未获得管理员授权 | 保持普通模式 |
| RESTORE_CONFLICT | 系统代理已被其他程序修改 | 不覆盖，展示可选择的恢复操作 |

错误码为产品内部约定，不假设内核已经提供完全相同的错误分类。无法可靠区分的情况，使用更宽泛提示并保留脱敏底层详情。

## 12. 打包、升级与源码交付

### 12.1 构建流程

1. 建立独立 Git 仓库和定制分支，保留上游历史及版权说明。
2. 固定上游提交、内核版本、Rust/Node/pnpm 工具链和依赖锁文件。
3. 先完成未改动上游的基线构建，再分批实现定制功能。
4. 在干净构建环境运行适用的前端检查、后端检查和关键测试。
5. 从构建输出组装 ZIP，不从日常正在运行的安装目录复制用户数据。
6. 检查全部执行文件和依赖来源，生成构建清单及 SHA-256。
7. 对自有程序使用独立的代码签名身份，私钥不进入仓库和发布 ZIP；不得冒用上游签名。
8. 在无开发环境、无原客户端、无已有服务的干净虚拟机上验收最终 ZIP。
9. 同时准备对应源码包、构建说明、第三方许可、修改说明和版本记录。

### 12.2 升级策略

首版禁用上游安装型自动更新，避免更新成安装版或覆盖到原应用目录。界面仅检查本产品版本并引导下载经过验证的 ZIP。

推荐升级流程：退出程序 → 下载新版本到新目录 → 校验签名或可信签名清单 → 迁移必要用户数据 → 执行配置格式迁移 → 验证运行 → 保留旧目录用于恢复。数据格式变更应先备份，标记 schemaVersion；回退程序时恢复匹配版本的数据备份。

哈希值仅用于校验完整性，不能代替发布者身份验证。后续自动更新应使用自有签名清单、公钥固定和失败回退机制，不沿用上游公钥与更新端点。

## 13. 测试计划与发布验收

### 13.1 必要自动化测试

测试聚焦容易造成错误链路、凭证泄露和恢复失败的逻辑，不为纯展示样式增加低价值测试。

### 13.3 v1.0 发布门槛

- 干净电脑无需安装 Clash Verge 即可从 ZIP 启动；标准包依赖条件明确，完整包运行时测试通过。
- 测试人员无需编辑 YAML 或 JavaScript，完成导入、填写、选节点、连接、断开全过程。
- 所有承诺支持的协议组合通过整链检测与实际应用验证。
- 人为断开前置或出口后，产品不自动把相关代理流量切到 DIRECT 或前置直出。
- 同时存在原版时不读取、改写或删除原版配置，不误结束原版进程。
- 正常断开和退出恢复本程序持有的系统代理；异常恢复按约定工作，限制已写入说明。
- 日志、默认诊断包和发行 ZIP 中没有真实订阅令牌、密码或用户备份。
- 不连接上游安装更新通道，不安装未告知的常驻服务。
- 产品签名与清单验证、对应源码和许可材料完备。
- 没有未解决的阻断级缺陷：错误出口、隐式直连、凭证暴露、无法恢复网络设置或影响原客户端。

性能目标先作为待测指标：在有效订阅和可用链路下，首连检测目标 30 秒内完成；故障在超时预算内给出原因；不以实验室单次结果作为对所有线路的速度承诺。

## 15. 角色分工与成本估算方法

| 角色 | 核心责任 |
| --- | --- |
| 产品负责人 | 确认目标用户、流程、服务范围、价格与验收结果 |
| 主开发 | 定制分支、便携化、链路模块、恢复、构建和版本维护 |
| 测试 | 干净系统矩阵、故障注入、共存验证、最终包验收 |
| 发布维护 | 签名、源码和许可材料、版本公告、反馈分类与支持记录 |
| 外部专业支持 | 对实际分发、宣传、服务模式及相关许可义务进行评估 |

一个人可以兼任多个角色，但发布验收尽量由未参与对应实现的人复核。首版不以未经验证的固定金额承诺开发总价。

预算使用以下公式：开发人日 × 实际人日单价 ＋ 测试投入 ＋ 签名证书 ＋ 专业审核 ＋ 发布托管 ＋ 维护预留。人日单价与证书等费用在采购时另行获取报价。

## 16. 收费验证、许可与运营范围

### 16.1 试用与价格假设

软件维护服务可先测试 99 元/年，首次人工配置服务可测试 199 元/次。价格是实验假设，不是市场行情；用户自备前置和出口资源，资源费用另计。

试用观察至少 14 个日历日，覆盖 10 名目标用户和至少 5 名付费用户。建议以以下条件决定是否扩大发布：

- 有效资源和支持系统下，至少 8/10 用户能够按指引独立完成首连。
- 连接失败能定位到可操作的环节，且未出现错误出口、凭证泄露或影响原客户端的阻断缺陷。
- 初次配置平均人工支持时间目标不超过 20 分钟；超出时重新评估服务价格与支持范围。
- 分开记录产品缺陷、供应商线路问题和系统环境问题，不用“总是能上网”作为产品指标。
- 记录后续使用和继续付费意愿；两周试用不能证明年费续费率。

### 16.2 GPL 与分发

Clash Verge Rev 的对应项目声明 GPL-3.0-only，mihomo 亦采用 GPLv3。定制分支的分发必须保留许可与版权、标明修改，并按许可证要求向接收者提供对应源码及构建所需材料。[Clash Verge Rev 许可](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.9/LICENSE)、[mihomo 许可](https://github.com/MetaCubeX/mihomo/blob/Meta/LICENSE)

产品允许收费。收费协议应围绕交付、维护、支持和独立服务制定，不额外剥夺接收者依 GPL 获得的复制、修改和再分发权利。不以客户端“不可复制、不可修改”作为商业壁垒。若未来加入独立在线服务，需另行明确服务与客户端的边界及许可。

逐项检查 WebView2、规则数据库、图标、字体与其他依赖的分发条件。不能只在关于页面写一句开源声明就完成全部义务。

## 17. 主要风险与处理决策

| 风险 | 处理方式 | 何时调整计划 |
| --- | --- | --- |
| 上游数据、服务和初始化耦合超预期 | 先完成 M0/M1，保持定制改动集中 | 便携骨架无法按预算隔离时重新估算，不急于做界面 |
| 固定内核不支持某组合 | 建立实测支持矩阵，提示具体限制 | 未测试协议不进入首版承诺 |
| TUN 权限与驱动故障 | 独立验收，普通模式可先发行 | 安全或恢复测试失败则延期 TUN |
| 凭证随配置暴露 | 本机加密、受限临时文件、诊断脱敏 | 出现泄露先停止分发并修复 |
| 代理退出后网络不可用 | 所有权记录、守护进程、恢复入口 | 任何阻断恢复缺陷均阻止发布 |
| 原客户端被影响 | 全面隔离，不复用服务与用户目录 | 共存测试失败则阻止发布 |
| 升级变成安装版或覆盖用户数据 | 禁用上游更新，独立升级与数据迁移 | 迁移或回退测试失败则停止更新 |
| 供应商问题吞噬支持时间 | 错误定位、明确支持范围、记录成本 | 试用支持超预算时收窄范围或调价 |
| 收费价值不足 | 小范围真实付费，记录独立完成率和继续使用意愿 | 用户主要需求已被原版满足时暂停扩大开发 |
| 许可或经营模式不适配 | 发布前核对源码义务及实际运营模式 | 不能满足条件时先调整分发和服务方式 |
