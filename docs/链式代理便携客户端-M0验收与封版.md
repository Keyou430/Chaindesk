## 4. 干净 VM 的验证边界

目标镜像为微软 Windows 11 Enterprise Evaluation 26H2 x64，build 26300.9457。镜像必须与微软公布的完整 ISO SHA-256 匹配后才允许启动。虚拟机使用 QEMU 11.1.0、WHPX、UEFI、4 个 vCPU、6 GiB 内存和新建的 64 GiB 虚拟磁盘，客体系统分区为 NTFS。

首轮安装在 Windows 重启后黑屏；保留磁盘、重新启动 QEMU 后安装继续。上游已确认 WHPX 的处理器重置和 XSAVE 状态问题。验收控制器改用 `-no-reboot`，只在 QMP 明确报告 `guest-reset` 且 QEMU 正常退出时重启进程；后续启动只从原虚拟磁盘引导，最多五次启动，共用 45 分钟总限时。此处理仅涉及一次性 VM，不修改宿主虚拟化或安全设置。依据：[WHPX 修复说明](https://lore-kernel.gnuweeb.org/qemu-devel/20261109004108.85808-3-mohamed@unpredictable.fr/T/)、[QEMU 启动参数](https://www.qemu.org/docs/master/system/invocation.html)。

## 5. 按序复核

开发机需已有 Windows SDK、微软 VS 安装器验证库及可用的 WHPX。QEMU 安装包按 `cleanVmEnvironment.qemu.installerSha512` 验证后解包到 `%USERPROFILE%/.cache/chaindesk/virtualization/qemu/`，不执行安装器；Windows ISO 按清单放入同一缓存根目录。完整 WebView2 CAB 解包到 `virtualization/payload/runtime/`，保留 CAB 内的版本目录。`run-clean-vm.mjs` 会重新核对镜像、QEMU 主程序和固件、WebView2 主程序及内核哈希。

从工程根目录的 PowerShell 7 执行：

```powershell
. ./scripts/chaindesk/bootstrap.ps1 -Install
pnpm.exe install --frozen-lockfile --registry=https://registry.npmjs.org
pnpm.exe chain:prepare --webview
$catalog = (Get-Content -Encoding UTF8 -Raw docs/engineeringBaseline.json | ConvertFrom-Json).buildToolchain.acceptedCatalog
Invoke-WebRequest -Uri $catalog.url -OutFile "$env:USERPROFILE/.cache/chaindesk/artifacts/$($catalog.fileName)"
pnpm.exe chain:verify-vs -CatalogPath "$env:USERPROFILE/.cache/chaindesk/artifacts/VisualStudio.17.14.44.vsman"
pnpm.exe chain:build-baseline -PinnedMsvc
pnpm.exe chain:archive-core-inputs
pnpm.exe chain:smoke
pnpm.exe chain:accept-vm
```

镜像或 QEMU 使用其他路径时，向 `chain:accept-vm` 传入 `--image <ISO绝对路径>` 和 `--qemu-root <解包目录绝对路径>`。验收成功后更新记录并提交经复核的源码，再执行 `pnpm.exe chain:seal-m0`；工作树不干净、证据或哈希不匹配时拒绝封版。输出为 `.chaindesk/releases/` 中的源码证据 ZIP 和 `M0-SEAL.json`，其中登记实际 Git 提交、程序哈希、截图哈希及归档 SHA-256。

本次封版标识为本地 Git 标签 `chaindesk-m0-20261111`；对应摘要和归档在 `.chaindesk/releases/m0-2026-11-10-<提交前12位>/`。`2026-11-10` 是技术基线确认日期，实际验收和封版日期由证据记录。M0 只接受未修改的上游应用源码；M1 及后续产品改动从封版提交之后开始，`releaseReady` 仍为 `false`。
