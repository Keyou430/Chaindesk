## 1. 确认口径

本文件确定开发采用的版本、接口、默认参数和验收方法，补充《详细执行方案》。发生差异时，本文件中的具体技术定义优先；产品业务范围仍以执行方案为准。

- **已核实**：读取固定提交的源码与锁文件，或实际下载文件并计算哈希；签名检查单独记录。
- **已决策**：本项目采用的设计约束，后续按此实现。
- **待验收**：需要客户端源码、构建环境、测试资源或干净虚拟机才能验证的行为，不提前标记通过。

基线初次确认时尚未引入客户端源码。本次 M0 实施已引入固定源码，在项目用户缓存中安装 Node/pnpm/Rust，并完成开发基线构建与本地隔离 SS/SOCKS5 链路验证；未在宿主启动基线上游桌面程序、未改系统代理或安装系统服务。完整过程、复用签名及验收限制见 [M0 实施记录](./链式代理便携客户端-M0实施记录.md)。

## 5. 凭证、文件权限与进程边界

1. 复用上游直接依赖 `windows 0.62.2`，启用 DPAPI、内存释放、文件安全、管道及进程 API 所需 features；不新增跨平台密码库或自定义加密算法。
2. `CredentialStore` 调用 `CryptProtectData` / `CryptUnprotectData`；采用当前用户范围和 `CRYPTPROTECT_UI_FORBIDDEN`，不使用 `CRYPTPROTECT_LOCAL_MACHINE`，不使用内置通用密钥。`credentials.bin` 由格式版本和 DPAPI blob 组成；明文只在必要处理窗口存在，释放 API 返回内存。
3. 敏感订阅缓存、凭证及 `data/runtime/<sessionId>/` 禁止宽泛继承，显式允许当前用户 SID 与 SYSTEM；无法设置所需权限时停止连接并报错，不回退到公共临时目录。此边界不声称防御同用户恶意进程或管理员。
4. 选择受限临时配置文件作为首版确定实现，不依赖尚未验证的内存配置入口。明文工作配置仅保存在本会话 runtime 目录；启动前校验权限，停止后清理，异常残留在下次启动时检查。不得承诺 SSD 上不可恢复擦除。
5. 长期保存最后可用配置的非敏感生成输入和凭证引用，不把含认证信息的 YAML 当作普通备份。未选择保存密码时，当前进程可以回退内存中的旧配置，重启后必须重新输入；恢复日志不含密码、令牌或完整订阅 URL。
6. 内核控制使用 `127.0.0.1:<随机端口>`，每实例生成 32 字节 CSPRNG 随机令牌；仅 Rust 后端持有。设置 `secret`，关闭外部 UI、外部 DoH、跨源访问和 mihomo 原生命名管道入口；端口竞争最多重试 5 次。
7. 自有 watchdog IPC 使用独立命名管道，显式 DACL 限制当前用户 SID 与 SYSTEM，拒绝远程客户端。仅接受恢复会话、结束守护和心跳等固定消息，消息上限 64 KiB；验证客户端 PID、创建时间、令牌身份及程序路径，不接受任意文件路径或命令。
8. 同一应用二进制提供受控 watchdog 模式；用保留的主进程句柄检测退出。恢复记录保存 sessionId、主进程身份、接管前快照和实际写入值；恢复前比对当前设置，冲突时保留用户或其他软件的新状态。
9. 系统代理读写集中封装固定版本 `sysproxy`，先验证其 WinINET/PAC/绕过规则能力，不直接复用上游面向全局服务的自动恢复行为。持久化采用临时文件、刷新和同卷原子替换；记录写入失败则不接管系统代理。
10. 内核使用确定的可执行路径与参数数组启动，不经过 shell。子进程环境采用必要 Windows 变量白名单，清除继承的 `CLASH_*`、代理环境变量及脚本钩子覆盖项；配置、控制令牌与路径只由本产品生成，防止外部环境覆盖受控接口或触发 `CLASH_POST_UP` 等行为。

mihomo 官方说明：原生命名管道控制接口不校验 `secret`。因此本项目不把“随机管道名 + secret”当作认证措施；自有管道需明确设置访问控制。依据：[mihomo 控制接口](https://wiki.metacubex.one/config/general/#外部控制-api)、[命名管道访问控制](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、[DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 6. 分流、DNS 与检测默认值

### 6.1 流量范围

首发只开放普通系统代理与本机 HTTP/SOCKS 入口。TUN 在 v1.0 首发隐藏，移入后续独立验收；不分发额外驱动、不安装常驻服务，也不开放通用提权入口。未遵循系统代理的应用不在普通模式覆盖保证内。

链式出口只含指定 SOCKS5，不加入 DIRECT 或前置直出备用。前置候选仍为 SS、VMess、VLESS、Trojan、AnyTLS，按具体传输/TLS 参数和固定内核逐组合验收；当前没有任何真实线路组合被本次核对标记为通过。首发承诺范围限定 TCP；UDP、QUIC 与 TUN 下的覆盖另行验证。

两套规则模板均先处理 localhost、`.local` 和回环、RFC1918、链路本地 IPv4 例外；国内直连模板再使用 `GEOSITE,cn,DIRECT` 与 `GEOIP,CN,DIRECT,no-resolve`，最后 `MATCH,<指定出口组>`。全代理模板省略 CN 直连条目。探测服务域名在局域网例外之后、其他公网分流之前显式进入被测链路，避免被 CN 规则误分流。

### 6.2 DNS

| 项目 | 确定定义 |
| --- | --- |
| 模式 | `dns.enable: true`、`enhanced-mode: redir-host`、`dns.ipv6: false`，内核全局 `ipv6: false` |
| 公网 DNS 监听 | 普通模式不配置公网或系统 DNS 接管；内部 DNS 解析不需要向局域网暴露服务 |
| 启动解析 | `default-nameserver` 与 `proxy-server-nameserver` 使用 `223.5.5.5`、`119.29.29.29`；只负责 DNS 服务及代理基础设施域名的启动解析，不依赖尚未建立的代理链 |
| 直连目标 | `direct-nameserver` 使用 `https://dns.alidns.com/dns-query#DIRECT` |
| 受代理目标 | `nameserver` 使用 `https://1.1.1.1/dns-query#<指定出口组>`，经同一完整链路解析 |
| 国内直连模板 | 为 `geosite:cn` 配置上述直连 DoH；全代理模板不加此策略 |
| 循环与降级 | 显式指定 DNS 连接路径，不配置直连 fallback；禁用 H3 优先，不关闭 TLS 验证 |

上述“启动解析”会直接查询代理服务地址等基础设施域名，应在隐私说明中公开。普通系统代理不会接管所有应用自行发出的 DNS；不能据此承诺整台电脑无 DNS 泄漏。固定内核对 DNS 路由的行为仍须通过断链和抓包验收。

依据：[mihomo DNS 配置及指定代理机制](https://wiki.metacubex.one/config/dns/)。

### 6.3 参数与错误语义

| 参数 | v1 默认值 | 验证口径 |
| --- | --- | --- |
| 订阅下载 | 单次总超时 20 秒，失败最多重试 2 次，退避 1 / 2 秒 | 只有网络错误、超时或可重试服务错误重试；认证和解析失败直接提示 |
| 订阅大小 | 解码后最多 10 MiB；最多 3 次 HTTPS 重定向 | 流式限制大小；跨主机不转发认证头 |
| YAML | 最大深度 32、节点最多 5000；拒绝别名和自定义标签 | 解析前及结构化转换时检查，不执行订阅脚本 |
| SOCKS5 认证 | 无认证，或用户名和密码各 1～255 个 UTF-8 字节 | 按字节校验，不能以字符数替代协议长度 |
| HTTPS 探测 | `https://www.gstatic.com/generate_204`，备用 `https://cp.cloudflare.com/generate_204` | 校验证书，要求 204，禁止重定向；不以 HTTP 200 门户页面判成功 |
| IPv4 查询 | 主：`https://api.ipify.org?format=json`；备：`https://www.cloudflare.com/cdn-cgi/trace` | 分别解析 JSON 的 ip 或文本的 ip 字段，严格接受 IPv4；响应最多 4 KiB |
| 单次探测 | 建连超时 3 秒、请求总超时 8 秒 | 显式绑定产品代理入口；关闭环境代理自动发现和 Cookie 持久化 |
| 自动前置 | 先筛选最多 3 个候选，再验证整链；整链并发上限 3 | 总检测预算 30 秒，到期取消未完成任务并反馈阶段；不是全订阅逐项测速保证 |
| 连接预算 | 从用户点击起 30 秒，包括候选检测、工作内核启动及复检 | 订阅下载是单独操作；超时给可操作提示，不假装连接成功 |
| 后台检查 | 前置 300 秒、整链 60 秒、出口 IPv4 300 秒 | 首连、前置切换、网络恢复后立即检查出口 IP；允许关闭后台定时检测 |
| 降级判定 | 连续 3 轮整链失败 | 单一探测服务失败先使用备用；仍无法区分时显示检测异常，不武断归因为出口认证失败 |

IP 服务返回不一致时显示“出口观察结果不一致”，保留时间与服务来源，不自动把任一结果设为预期 IP。用户未设置预期 IP 时只展示观察值；不以出口服务地址等于出网 IP 为成功条件。查询服务故障不触发切换出口或隐式直连。

用户名和密码长度依据 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)。IP 查询接口依据 [ipify 文档](https://www.ipify.org/)和 [Cloudflare trace 说明](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/)。时间、大小和并发数是本次确定的工程初值，不是已测性能结论。

## 7. 构建、签名与环境变量

| 配置 | 确定用途 |

| `NODE_OPTIONS=--max-old-space-size=4096` | 前端与 Tauri 构建进程 |

| 签名私钥 | 由发布专用签名设施提供，不进入源码、普通 CI 日志或 ZIP；当前不生成或预置发布者私钥 |

开发依赖通过 `pnpm install --frozen-lockfile` 安装，Rust 构建与测试使用 `--locked`；先完成联网获取，再验证锁文件，正式组装阶段仅使用核实过的资源缓存。前端执行 `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm test`；Rust 执行格式检查、Clippy 和相关测试。M0 已实际运行的检查及结果以实施记录为准，未执行项不标为通过。

自有可执行文件使用 Windows Authenticode SHA-256 签名和 RFC 3161 时间戳；发布清单采用 minisign 格式，复用上游 `minisign-verify 0.3.0` 验证独立产品密钥的签名，验证公钥固定在程序中。首发禁用 Tauri 上游安装型更新，不沿用上游更新公钥、端点或签名身份。证书主体和实际密钥属于发布资产，必须由项目实际持有后登记，不能在技术文档中虚构。
