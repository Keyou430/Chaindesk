# ChainDesk M2 implementation and acceptance

M2 is sealed as a development milestone. The minimal import, fixed-exit connection and credential workflow passed 85 checks in a disposable Windows 11 26300.9457 guest under a standard user. M3 reliability and M4 signed release acceptance remain separate gates.

## Scope and reuse

The approved execution plan sections 6 and 14.3 define this change. Local tracking is `.chaindesk/remaining-work/M2-M5-local-issue.md`; no GitHub issue or outbound message was created.

| Import path | Core signature | Responsibility and reuse |
| --- | --- | --- |
| `crate::config::chain::importer` | `parse(source: String, name: String, update_url: Option<String>) -> Result<Subscription>` | Scan before deserialization; retain the protected original source; produce stable node identities and explicit rejections. |
| `crate::config::chain::builder` | `build(front, endpoint, authentication, preset, mixed_port) -> Result<Mapping>` | Generate one selected front and one fixed SOCKS5 exit; never inherit subscription listeners, scripts or remote providers. |

No package versions changed. `unsafe-libyaml 0.2.11` was already locked transitively and is now referenced directly for token inspection. Enabling cancellation on the existing `tokio-util 0.7.20` adds its existing `futures-util` dependency edge. The custom lockfile digest is recorded separately from the immutable upstream baseline.

## Defined behavior

| Boundary | Implemented definition |
| --- | --- |
| Imports | Explicit local file or HTTPS URL; optional explicitly selected `127.0.0.1` HTTP proxy; no environment proxy discovery. |
| Download | 20 seconds per attempt, at most three attempts with 1/2-second backoff, at most three HTTPS redirects; no HTTP downgrade. |
| Parsing | 10 MiB decoded UTF-8, 5000 nodes, 32 collection levels, token/scalar budgets; reject YAML aliases, anchors and tags before serde expansion. |
| Node identity | Versioned SHA-256 over canonical allowed fields; display names do not alter identity; distinct authentication remains distinct. |
| Eligibility | Validate required fields and supported transport profiles; retain visible rejection reasons, exclude the configured exit endpoint and allow manual exclusions. Structurally invalid announcement entries are ineligible. |
| Exit | IPv4 or normalized IDNA hostname, port 1–65535; either no authentication or both fields of 1–255 UTF-8 bytes. |
| Persistence | `settings.json` contains no authentication; `credentials.bin` uses current-user DPAPI with the `CDP` format header. The original subscription and its update URL are protected too. |
| Commit ordering | Preserve the complete previous protected revision until the settings pointer commits. Remove unremembered authentication afterwards and again on load after an interrupted cleanup. Publish already committed state even if cleanup fails; require recovery before connection. |
| Connection | A cancellable 30-second budget covers native validation/application and working HTTPS/IPv4 checks. System proxy acquisition follows successful checks. M2 uses the working core; isolated pre-application diagnostics are M3. |
| Routing | Loopback, RFC1918, link-local and `.local` exceptions; explicit observation-service rules; optional pinned CN geo rules; final MATCH contains only the fixed exit. |
| Disconnect | Restore only owned proxy values, stop only the owned core and remove working/validation YAML. Never silently substitute DIRECT or a front-only route. |
| UI and privacy | Explicit probe consent, masked subscription URL/password, no credential localStorage, redacted state/runtime preview, no automatic connection after restart. |

The accepted harness and both guest helper scripts were independently read from the normally shut-down guest disk and byte-compared with this checkout. The source archive preserves actual build-checkout bytes at its root and includes a separate canonical Git archive and source correspondence record. The payload manifest records the M1 parent commit used when building; the seal records the final M2 commit/tag and verifies the actual source fingerprint.

Failed runs are not acceptance evidence. They exposed fixture issues that were reproduced and fixed: Trojan user-array serialization, TLS certificate paths outside the fixture core's allowed home, read/write access requested by a read-only credential load, loss of a redirected child process exit code without a retained handle, and PowerShell 5.1 serializing Provider properties attached to log strings. Test evidence uses an explicit direct transport independent of the proxy under test.

M3 still owns isolated probes, automatic selection, last-known-good restoration, persistent proxy ownership/watchdog recovery and redacted diagnostic export. M4 still owns standard/full signed release packages, licensing and final environment acceptance. M0 and M1 seals remain immutable.
