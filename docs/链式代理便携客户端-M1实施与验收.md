# ChainDesk M1：便携骨架实施与验收

本阶段依据执行方案 14.2 和用户已批准的本地 M1 Issue 草案实施。当前状态：M1 开发骨架已通过 61 项标准用户虚拟机检查，2026-11-12 完成本地阶段封版。标签：`chaindesk-m1-20261112`。

M0 已封版：提交 `fc1f269bb3e5df1460207530d2c89b2d2a623485`，标签 `chaindesk-m0-20261111`。M0 封版归档、已验收程序和证据保留原始字节。

## 1. 交付顺序与影响面

| 顺序 | 实现 | 主要入口与影响 |
| --- | --- | --- |
| 1 | 独立产品身份 | Tauri 产品名 `ChainDesk`，标识 `local.chaindesk.portable`；窗口、托盘、侧栏和图标独立；不注册上游 URL 协议、自启动或更新插件 |
| 2 | 数据与运行环境隔离 | 可执行文件相邻 `data/`；仅允许可写、本地固定 NTFS 卷；日志、备份、临时文件、WebView 用户目录均在该目录；启动失败不给 AppData 回退 |
| 3 | 私有控制与内核生命周期 | 显式启动 `core/mihomo.exe` 并校验哈希；每次实例生成控制端口、随机令牌和运行目录；现有 Windows Job Object 只管理本产品子进程 |
| 4 | 端口和代理共存 | 复用既有端口扫描；启动后核实代理监听 PID；竞争时最多启动 5 次；系统代理适配器拒绝其他应用的活动代理/PAC，仅恢复本实例仍拥有的设置 |
| 5 | 开发打包和虚拟机验证 | 固定 MSVC 构建、开发完整 ZIP、文件及源码哈希清单；在独立虚拟机中与 M0 上游基线程序共存 |

Windows 的服务安装、TUN、自启动、启动脚本和上游升级入口已关闭，后端同时拒绝调用。现有前端页面、配置事务和状态通知继续复用；简化首页与链路业务属于 M2。

## 2. 复用路径与核心调用

| 现有资产 / Import Path | 核心签名 | 本阶段适配 |
| --- | --- | --- |
| `crate::utils::dirs` | `app_home_dir() -> Result<PathBuf>` | Windows 返回已校验的相邻 `data/`；其他平台保留原路径分支 |
| `crate::utils::server` | `check_singleton()`、`random_token() -> Result<String>` | 复用实例锁与认证本地服务器；锁和认证材料位于独立数据目录 |
| `crate::core::owner_identity` | `create_private_current_user_file(&Path)`、`create_private_current_user_directory(&Path)` | 包装已有 SID / DACL 工具，文件和目录只授权当前用户与 SYSTEM，不接管其他用户目录 |
| `crate::config::{Config, MixedPort}` | `Config::runtime_config_yaml()`、`MixedPort::desired()` / `effective()` | 继续使用配置草稿、校验及持久化；最终运行配置施加便携约束，界面读取实际端口 |
| `crate::core::listener` | `loopback_tcp_listener_owner(u16) -> io::Result<Option<u32>>` | 复用原 Windows TCP 表解析工具，将监听归属纳入内核就绪检查 |
| `crate::core::CoreManager` | `start_core_by_sidecar()` | 保留日志读取、退出通知和 Job Object；替换 Windows 路径、环境与控制连接适配 |
| `crate::core::Sysopt` | `update_sysproxy()` | 保留系统代理模型及调用串行化，交由 `core::portable_proxy` 操作 WinINET LAN 设置 |
| `src/services/cmds`、现有 mutation / store | 现有设置命令与状态事件 | UI 隐藏不支持的入口，不增加第二套状态管理 |
| `scripts/chaindesk/build-baseline.ps1` | `-PinnedMsvc -Portable` | 复用固定编译器和基线初始化，分开记录便携构建日志 |
| `scripts/chaindesk/run-clean-vm.mjs` | `--milestone m1 --base-evidence <json>` | 复用 QEMU、隔离 HTTP 控制器及标准用户；公共 CDP 调用提取到 `vm-debugger.ps1` |

没有新增依赖包；仅启用现有 `windows-sys` 的 WinINET 功能。两个上游锁文件保留原始字节。

## 3. 运行与工程约束

```text
ChainDesk/
  ChainDesk.exe
  core/mihomo.exe
  resources/rules/{geoip.dat,geosite.dat}
  runtime/                         # 开发完整包附带固定 WebView2
  data/                            # 首次运行创建，不进入干净 ZIP
    logs/ backups/ temp/ webview/
    runtime/<随机会话>/
```

- 构建沿用 Node.js `26.13.0`、pnpm `12.16.1`、Rust `1.99.1`、MSVC `14.44.35229` 和 Windows SDK `10.0.26100.0`，不使用容器。
- 内核固定 `v1.19.33`，完整包 WebView2 固定 `157.0.4341.46`。应用进程设置自己的 `TEMP`、`TMP`、WebView 环境；内核以环境白名单启动，不继承宿主代理和内核路径变量。
- 控制 API 仅监听 `127.0.0.1`，每实例使用 32 字节随机令牌，不启用原生控制管道。前端配置读取移除令牌；权限清单禁止改控制连接、修改核心基础配置与升级内核。
- 运行配置强制关闭 LAN、IPv6、TUN 和额外代理监听。M1 只验证便携骨架；整链 DNS / 路由策略在 M2、M3 实现。
- 系统代理操作限定 LAN；上游 setter 会同时改写 RAS 连接，因此用窄 WinINET 适配器扩展现有调用。恢复时比较原始注册表值和实际活动标志，外部改动后放弃恢复。
- `pnpm chain:build-portable` 构建；`pnpm chain:assemble-portable --full` 生成开发完整 ZIP；`pnpm chain:accept-portable-vm --base-evidence <json>` 运行标准用户验收。构建与打包均不会启动宿主 GUI。

开发包在 M1 提交前构建，因此 `payload-manifest.json` 的 `sourceCommit` 记录构建时的 M0 父提交；`sourceFiles` 和 `sourceFingerprint` 绑定实际 M1 文件字节，封版摘要另外记录最终 M1 提交和标签。

已完成的静态与本机验证：固定 MSVC 开发构建、前端类型检查、前端全量 ESLint、脚本 ESLint、Vitest（10 文件、34 用例）及后端 6 项就绪 / 生命周期回归用例通过。端口冲突的最小复现证明：控制 API 可返回成功，而代理端口实际绑定失败；因此补上监听 PID 检查，并增加对应的有界重试回归用例。端口恢复后的前端运行配置预览也与实际端口同步。

全目标、全特性 Clippy 在 `-- -D warnings -A dead_code` 下通过。未豁免的严格命令仍受 13 项保留的旧代码未使用告警影响，包括停用的窗口状态、旧目录修复和服务残留辅助函数；本阶段保留这些资产，不为消除告警删除旧代码。新增代码的 Clippy 违规已修正，未在源码中增加全局 lint 豁免。

虚拟机基于重新安装的 Windows 11 x64 评估系统，正常关机后创建差分副本。共存对象为已封版 M0 上游基线程序，使用验收夹具自己的配置和内核；夹具关闭原版自动检查更新与全局热键，不对热键共存作验收结论。未覆盖官方签名安装包、原版服务模式或 TUN。QEMU 无 TPM、Secure Boot，本轮不声称完成平台安全认证。

验收过程中已纠正：中文路径下的解压工具兼容问题、将未正常关机的旧 M0 磁盘误作后续测试基底、界面返回保存端口而非实际端口，以及只检查控制 API 的就绪误判。不可写目录夹具曾在恢复目录权限时错误要求管理员权限；该目录仅存在于一次性虚拟机，取消无必要的权限恢复；对话框确认改为核实 PID 后发送原生消息，排除前台焦点竞争。失败记录保留在本地，均未算作通过。
