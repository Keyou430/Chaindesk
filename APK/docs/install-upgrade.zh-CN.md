# ChainDesk Android 开发版安装与使用

这是一份用于自用验证的开发安装包。当前版本名称为 `0.1.0-dev.1`，
使用 Android 调试签名。ARM64 真机、厂商兼容性和长期使用验收尚未完成。
构建目录、校验值和本次验证结果见 [开发状态](development-status.md)。

## 安装与首次连接

1. 普通 ARM64 手机选择文件名含 `arm64-v8a` 的 APK；`x86_64` 包用于
   本项目的模拟器验证。将 APK 复制到手机，在文件管理器中打开，按系统提示
   允许该文件来源安装应用。系统版本下限设置为 Android 8.0，实际兼容性仍需验证。
2. 打开应用，进入“配置”，选择 YAML 文件，或填写 HTTPS 订阅链接后点击
   “从链接导入”。支持 Clash / Mihomo 节点格式；订阅最多 10 MiB、5000 个节点。
   节点通过格式筛选仅说明可供尝试，不代表该协议已通过手机实测。
3. 填写固定 SOCKS5 出口的主机和端口。主机框不填 `socks5://`、路径或端口；
   需要认证时填写用户名和密码。前置节点和出口应为两个不同端点。
4. 选择路由预设、前置节点并点击“保存配置”。“全部代理”仍保留页面列出的
   局域网、回环和启动解析例外；“国内直连”另外使用随包国内规则。
   “预期出口 IPv4”可留空；填写后，地址不匹配会拒绝连接。
5. 返回“连接”，点击连接，允许所需的通知、VPN 授权。
   使用私有地址或局域网例外时，系统还可能要求本地网络权限。
   等待显示“整链验证通过”。“正在验证整链”表示检测尚未完成。
6. 使用一个实际业务应用确认 TCP 访问及出口符合预期。出口 IPv4 的观察结果
   不证明供应商提供住宅、独享或永久固定地址。

订阅和出口凭证只保存在本机加密资料中。关闭记住凭证后，重启应用需要重新输入；
不要把订阅链接或密码放进截图、聊天或问题报告。

## 断开、失败与诊断

- 修改订阅、出口或路由前先断开，等待“已断开”。连接期间可切换前置，
  切换失败时在连接预算内尝试恢复上次验证通过、且仍被当前配置允许的前置。
- “链路需要恢复”且 VPN 仍接管时，受代理流量保持阻断。检查前置、出口认证
  和网络，或切换前置；主动断开后，流量交还系统。
- 非 DNS UDP（包括 QUIC）和 IPv6 在当前 VPN 接管期间按阻断策略处理。
  依赖这些协议的应用可能不可用；IPv6-only、NAT64 和 Private DNS 的完整矩阵
  尚未验证。
- 强行停止、进程或原生崩溃、撤销 VPN 授权、被其他 VPN 替换，都可能移除
  系统 VPN 路由。此开发版不提供 VPN 进程退出后的系统级断网保护。
- 进入“诊断”，生成预览并核对后导出。状态改变后需重新预览。
  导出包含版本、状态和错误分类，不包含订阅链接、密码和完整节点配置。

## 更新与恢复

更新前先断开 VPN，再安装包名相同、签名相同且 `versionCode` 更高的 APK。
保留原应用，不先卸载、不清除数据。安装成功后重新打开，确认配置仍在，
重新输入未记住的凭证并再次连接验证。

Android 会拒绝不同签名的覆盖安装，通常也会拒绝版本号降低。
需要恢复旧代码时，应由同一签名生成版本号更高的恢复包。当前调试身份的
升级验证不等同于正式长期签名及备份验收；不要据此建立正式发布渠道。

卸载、清除数据或丢失本机加密密钥可能使资料无法恢复。
复制加密文件到另一台手机不能替代凭证备份。遇到密钥或资料损坏提示时，
先保留诊断，再使用自己持有的订阅和出口资料重新配置。
